รายงานเป็นภาษาไทย กระชับ ตรงไปตรงมา

## หลักตัดสิน (สำคัญ — อย่ารายงานมั่ว)

ทุกบรรทัดที่ grep เจอ = "จุดที่ต้องไปเปิดดู" **ไม่ใช่** "ช่องโหว่" ทันที
ต้องเปิดไฟล์อ่านจริงแล้วถาม 2 คำถามก่อนเสมอ:
1. ข้อมูลนี้มาจาก "คนอื่น" (URL, โค้ดที่วาง, ไฟล์) หรือจาก "ระบบเราเอง"?
2. ก่อนเอาไปใช้ มีตรวจ **ชนิดข้อมูล** ไหม (ไม่ใช่แค่เช็คว่า "มีค่า")?

เข้าเงื่อนไขทั้งคู่ (มาจากคนอื่น + ไม่ตรวจชนิด) = ช่องโหว่จริง
**ห้ามรายงานว่าเป็นช่องโหว่ถ้ายังไม่ได้เปิดไฟล์อ่าน**

## ขั้นตอนตรวจ

รันทีละขั้น แล้วเปิดไฟล์อ่านทุกจุดที่เจอ:

1. **ช่องทาง XSS** — `grep -rn "innerHTML|dangerouslySetInnerHTML|eval|document.write|insertAdjacentHTML" src/`
   (ปกติต้องไม่เจอเลย เพราะ React หนีอักขระให้อยู่แล้ว — เจอเมื่อไหร่ = เรื่องใหญ่)

2. **จุดรับข้อมูลนอก** — `grep -rn "JSON.parse|atob|Object.assign|localStorage.getItem" src/`
   ทุกจุดต้องผ่าน `normalizeData()` หรือมีการตรวจชนิดของตัวเอง
   ถ้าเจอ `Object.assign` ที่ยัดข้อมูลจากผู้ใช้เข้า state ตรงๆ = ช่องโหว่ (เคยเกิดมาแล้วที่ commit 2384137)

3. **อ่านค่าจาก URL** — `grep -rn "location.search|location.hash|URLSearchParams" src/`

4. **ความลับที่เผลอฝัง** — `grep -rniE "api[_-]?key|password|secret|token|private[_-]?key" src/`
   หมายเหตุ: `artyz-coach-2026` ใน license.ts เป็นค่าที่ผู้ใช้ยอมรับความเสี่ยงแล้ว ไม่ต้องรายงานซ้ำ

5. **dependency** — `npm audit --omit=dev` (ต้อง set PATH ก่อน ดู CLAUDE.md)

6. **gate ไม่หลุดเข้ารุ่นส่วนตัว** — ถ้ามี `dist/` อยู่ ให้ตรวจว่าไฟล์ `dist/assets/*.js`
   **ต้องไม่มี** คำว่า `artyz-coach-2026` (ถ้าเจอ = โค้ดตรวจสิทธิ์หลุดเข้า build ผู้ใช้ = บั๊ก)
